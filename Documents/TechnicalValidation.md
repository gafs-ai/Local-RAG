### DB-01: DiskANN対応エンジンの版差

初期構成での状態: 未解決だった。現在はユーザー指示による別プロセス化で解消（7節）。

公式資料ではDISKANNは3.1以降。一方、NuGet 1.0.0の組み込みエンジンは3.0.5であり、以下の定義は実際に構文エラーとなった。

```sql
DEFINE INDEX probe_vector ON probe FIELDS embedding
    DISKANN DIMENSION 3 DIST COSINE TYPE F32;
```

エラー抜粋:

```text
Parse error: Unexpected token `an identifier`, expected Eof
... embedding DISKANN DIMENSION 3 ...
              ^^^^^^^
```

初期診断プログラムはバージョンを判定して非対応を明示していた。HNSWや別DBには置き換えなかった。

当時の検討候補（現在は別プロセス化を採用）:

1. 公式.NETプロバイダーのネイティブ層を対応エンジンへ更新する方法を調査。
2. ABI・シリアライズ・Windows配布を確認し、再現可能なソースとビルド手順で組み込む。
3. 公式プロバイダーの更新が困難なら、C#インターフェースを維持した小さなRust組み込みアダプターを評価。
4. DBを外部サーバーに変更する案はEmbedded要件の変更になるため、既定の解決策にはしない。
5. 作成・検索・追加・更新・削除・再起動・検索対象フィルターを実機検証する。

## 4. 自動テストの対象

- リモートURL・認証情報付きURLをAI接続先として拒否。
- クラウドまたは不明なrecipeのモデルへ本文を送らない。
- 打ち切られたチャット応答を完成済みとして受け取らない。
- 無効な設定やキャンセルで、既存の保存済み設定を上書きしない。
- 未対応版の設定を黙って初期値に戻さない。
- 日本語フォルダ・モデル設定の保存と復元。
- 周期の処理終了前には待機を開始せず、同時起動を拒否。
- 周期が失敗しても間隔を待ち、即時ループしない。
- 検索用本文から除去された機密ヘッダーでも返却拒否。
- 返却候補に追加された機密文字も検査。
- 不正な正規表現、分類器エラー、判定不能では本文を返さない。
- 明示的な検査無効化を未検査として区別。
- DBチェックポイントの保存・再接続・未完了工程の回復。

LLM機密分類器はテストダブルを使用。実モデルによる機密検出精度やMCP出口との結合を検証したものではない。

### 7.2 導入・接続・終了

`db .local/auto-install-verification`でキャッシュがない状態から約307MiBをアプリ自身で取得。ハッシュ照合、原子的配置、起動、診断、通常終了まで成功した。起動時に既存バイナリも検証する。不一致の既存ファイルを実行・上書きしないことを自動テストで確認。

初期試行ではHTTP SDKがSignInに先立って匿名の初期化クエリを送るため認証に失敗した。認証情報を構築時のSurrealDbOptionsへ渡し、名前空間・DBを明示定義する方式で解消した。

終了通知は専用の非表示コンソールに限ってCTRL_BREAKを送る。補助プロセスが通知直後にコンソールを切り離すと終了コード`0xC000013A`になる競合を検出し、ハンドラーを保持したままDB終了を待つ方式に修正した。修正後の通常終了に成功。プロセス名による一括終了・強制終了は使用していない。

自動テストで次を確認:

- 終了設定OFFでDBが生存し、同じ管理情報で再接続して管理を引き継げる。
- 他の保存先から既存DBへ接続したクライアントは、終了設定ONでもそのDBを終了しない。
- DB以外のポート利用や認証未設定を勝手に置換しない。
- PIDだけでなく起動時刻・実行ファイルを照合し、不一致は所有プロセスと扱わない。
- パスワードのDPAPI保存と読み出し、設定のDBポート・終了設定の保持、旧設定への既定値適用。

### 10.1 構成と互換性修正

ユーザー指定のチャットモデルは`Gemma-3-4b-it-mm-NPU`。モデル一覧でローカル導入済み、recipe=ryzenai-llm、context_length=4096を確認。Embeddingは`nomic-embed-text-v2-moe-GGUF`、recipe=llamacpp、ローカル導入済み、実行時context_length=8192だった。

JSON・段落範囲の検査は緩めていない。機密ラベルを整形で除去しても原文で機密検査する仕様も維持した。入力形式の変更は設定版とEmbedding空間の識別へ反映し、旧形式の索引を再利用しない。通常のユーザー設定ファイルは変更していない。
