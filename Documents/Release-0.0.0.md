# 0.0.0 リリース判定と利用上の制約

状態: **開発・評価版0.0.0-rc.3。正式0.0.0は未リリース。** ユーザーからChatGPTの新しい会話で合成文書を取得できたとの報告を受けた。2026-11-02のユーザー指定により、今回はGitHubへのソース反映を区切りとし、0.0.0のタグ・GitHub Releaseは作成しない。最低限の実用性を評価し、改めて公開の指示を受けるまで正式リリースを保留する。

## 対応範囲

- Windows 11 x64、C#/.NET 10、Lemonade Server、SurrealDB 3.3.5別プロセス、DiskANN。
- 指定拡張子のUTF-8テキスト（BOM可、既定.txt/.md）。ファイル追加・変更・削除の探索、低優先度の常駐、完了後15分待機（変更可）、途中再開。
- 分類・不要段落除去・段落単位の分割・Embedding。プロンプト・カテゴリ・拡張子別処理・共通取得設定は専用の管理画面で編集。配布プロンプトは読み取り専用でコピーして利用。
- 管理画面とMCPのsearch/fetch。原文・返却候補のパターンとローカルLLM機密検査。
- Word・PDF・音声・画像・他の文字コードは後続版。Windowsログオン時の自動起動登録、専用インストーラー、履歴閲覧、バックアップUIは含まない。

## 起動

ZIPをフォルダへ展開し、`LocalRag.Desktop.exe`を実行する。.NET Desktop Runtime 10.0 x64とASP.NET Core Runtime 10.0 x64が必要。.NET 10 SDKを導入済みなら別途不要。Lemonade Serverと使用モデルは事前に用意する。

フォルダとチャット・Embeddingモデルを設定して保存すると監視を開始する。既定の保存先は`%LOCALAPPDATA%\LocalRAG`。閉じるボタンでトレイ常駐、トレイまたは画面の「アプリを終了」で終了する。DBが未導入の場合は検証対象の公式バイナリを取得し、SHA-256照合後に起動する（初回約307MiB）。

MCPとChatGPTへの接続は[MCPConnection.md](MCPConnection.md)を参照。

## 初期版の制約

入力は1ファイル256KiB、既定6,000文字、1チャンク1,200文字まで。モデルの上限も別途適用する。段落内の再分割は未対応。入力超過・不正JSON・接続障害は保留し、原文を黙って切り詰めない。

検証モデルはGemma-3-4b-it-mm-NPUとnomic-embed-text-v2-moe-GGUF。nomicの512トークン上限を、UTF-8バイト数+256という保守的な式で検査するため、接頭辞込みの入力は256バイト以下となり、日本語の実用長は短い。少数の短文による成立確認であり、長文・多数文書の処理速度や検索品質を保証した結果ではない。

モデルのスキーマ不正には意味を変えないコード補正と1回の差し戻しを行い、それでも不正なら保留する。同じJSONオブジェクトを反復した応答は、すべて同一内容で重複キーがない場合だけまとめる。複数の異なる回答から都合のよいものを選ばない。意味的な分類・機密判定ミスは残り得る。

検索は取り込み処理の終了を待つ。MCPは待機を含め100秒で打ち切るので、取り込み完了後に再試行する。機密検査が公開文書を保留・拒否することもある。標準では検査を有効にし、検査障害も非開示にする。

## 検証・リリース判定

現行ソースの自動テストは124件、失敗0、スキップ0（実DB11件を含む）。以前の実モデル・実DB・stdio→認証付きHTTPの実MCPクライアント試験では、短い合成4文書の取り込み、検索、全文取得、機密拒否、変更後の旧版非取得に成功した。専用ワーカーとDBの強制終了後、未完成版を隠し、未完了Embeddingのみ再開する試験にも成功。詳細と初回失敗は[TechnicalValidation.md](TechnicalValidation.md)に記録する。

設定管理画面の追加後、プロジェクトの説明書とC#コードを全文で実モデル評価したところ、分類またはEmbeddingの入力長検査で両方とも保留となった。設定UIの保存・再表示は確認済みだが、実文書の長文処理は改善が必要。今回の管理画面は以前のrc.3配布ZIPには含まれず、更新したソースのビルドで利用する。

候補ZIPを展開したアプリで起動とMCP待機を確認。画面を閉じてトレイ常駐した後も、インストール済み中継から検索・全文取得に成功した。

ChatGPTの新しい会話で「水やり」に対するguide.txtの本文・出典・文書IDが返ったことを、ユーザー提供の結果で確認した。個々のsearch/fetch呼び出し履歴はこの会話では確認していない。接続成立の証拠とし、実用性・検索品質・機密検査全体の合格とは区別する。

今後の評価項目: 代表的な日本語文書の取り込み可能な長さと検索品質、継続運用時の追加・更新・削除と復旧、ChatGPTでの機密拒否・検査失敗の非開示、初回導入から取得までの手順。特に前述のnomic入力上限が実用性に与える影響を確認する。正式配布物の確定とGitHubタグ/Releaseは評価後の別作業とする。API Platformは前提にせず、ブラウザ対応は後続で設計する。

## 配布の作成

Windows PowerShellで`./scripts/Package.ps1 -Version 0.0.0-rc.3`を実行すると、`artifacts`内の新規フォルダへ配布ZIP、依存ライセンス一覧、SHA-256を作成する。Git作業ツリーがクリーンなら対応するHEADのソースZIPも作る。変更未コミットの場合は検証用と明記し、ソースZIPは作らない。
