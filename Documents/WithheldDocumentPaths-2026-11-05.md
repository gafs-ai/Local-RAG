# 非開示文書の原本パス通知（2026-11-05）

秘匿検査で本文を返せない場合でも、ユーザーが原本を開けるよう、検索・全文取得に原本のフルパスを追加した。再取り込みは不要で、更新後の本体で既存索引にも適用する。

## 返却仕様

`withheld`と`pending`では、MCPは`id`、`decision`、`source`だけを返す。`source`は実ファイルのパスである。本文・要約・コード・章タイトル・親子チャンク情報・段落番号・スコア・詳細判定理由は返さない。古いサーバー等でパスがない場合はIDと判定だけを扱い、パスを推測しない。

```json
{
  "id": "7619c210-8546-4eb5-b598-94834cb6a0d2",
  "decision": "withheld",
  "source": "C:\\Documents\\内部資料.txt"
}
```

この仕様ではファイル名・フォルダ名を含むパスをクライアントへ提供する。パターン検査・LLM検査は引き続き実行し、本文の非開示判定は変えない。取得前後の鮮度確認、対象フォルダ、ignore、カテゴリ・設定一致の確認も維持する。変更済み・削除済み・対象外の文書からパスを返す機能ではない。MCP呼び出し全体のタイムアウトや接続障害は従来の固定エラーを返す。

管理画面は非開示の判定、原本パス、エクスプローラーで開く手順を表示する。配布用プラグインの案内も、パスを文字列として提示してユーザー自身に開いてもらう内容へ変更した。AIがファイルを直接読んで機密検査を迂回する指示にはしない。MCPの`fetch`引数は引き続き文書IDのみである。

## 検証

- パターン一致の`withheld`、LLM検査失敗の`pending`で本文がnull、原本パスが一致することを実DBで確認。
- 誤ったアダプターが本文や章情報を渡しても、MCP投影がID・判定・パス以外を出さないことを確認。
- 実HTTP MCPクライアントとstdio中継で検索・全文取得を実行。日本語・空白・`#`・角括弧を含むパスも文字列として一致。
- 別章に秘匿情報がある親チャンク、コード説明に秘匿パターンがある結果も、本文や構造情報を出さないことを確認。
- 元ファイルの変更・削除後はパスを含めて取得対象外であることを確認。
- `TestResults/withheld-path-targeted.trx`：53成功・失敗0。
- `TestResults/withheld-path-final.trx`：306成功・失敗0・1スキップ。スキップは別途実行するLemonade起動終了試験。
- Desktopの別出力先`.local/withheld-path-build/`と診断ツールのビルド：警告0・エラー0。配布スクリプトのPowerShell構文検査も成功。

Computer Useは禁止中のため使用していない。実画面での表示と、この会話に接続されたプラグインの更新後の動作は未検証。配布用スクリプトを修正したが、インストール済みプラグインのキャッシュや登録は変更していない。

ユーザーによるアプリ終了後、通常の`src/LocalRag.Desktop/bin/Release/net10.0-windows/`へ配置した。ソリューションのReleaseビルドは警告0・エラー0。Core・Infrastructure・MCPの配置済みDLLが各プロジェクトの最新ビルドとハッシュ一致することを確認した。設定・索引データは変更していない。
