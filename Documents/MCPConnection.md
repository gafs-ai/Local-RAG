# MCP接続手順（バージョン0.26.3）

## 利用条件

Local RAGの管理画面でフォルダ・Gemma等のチャットモデル・Embeddingモデルを保存し、取り込みを完了させる。「接続状態」のMCPが待機中であることを確認する。ウィンドウを閉じてもトレイ常駐中は利用できる。「アプリを完全終了」では接続も停止する。

現在は設定した拡張子のテキストと9言語のソースコード説明検索（文字コードは自動判別または明示指定）を対象に、`search(query, limit=5)`と`fetch(id)`だけを公開する。limitは1～10、queryは1～1000文字。fetchは検索で返されたUUIDを指定し、現在公開中の原文全文を取得する。任意パス・SQL・書き込み・原本バイナリの取得は提供しない。履歴版・ページング・画像は後続版で扱う。

## このPCのMCPクライアント

コード説明検索では`search`の`text`にAI説明文と元コードを返し、`source_kind`（function/class/file）、`start_line`、`end_line`を追加する。`container_id`は所属する単位のIDで、`fetch`の引数には使わない。`fetch`は文書IDによる元ファイル全文の取得を維持する。説明はAI生成で、原文コードによる確認が必要。秘匿判定で拒否・保留となった場合は、これらの情報も返さない。

アプリの配布フォルダ内の`LocalRag.Mcp.exe`をstdioサーバーとして登録する。例えば汎用的な設定形式では次のようになる（実際の形式は利用するクライアントに合わせる）。

```json
{
  "mcpServers": {
    "localrag": {
      "command": "C:\\Apps\\LocalRAG\\LocalRag.Mcp.exe",
      "args": []
    }
  }
}
```

保存先を変更した場合は`args`を`["--data-dir", "C:\\LocalRagData"]`のように指定する。絶対パスを使う。アプリと中継は同じWindowsユーザーで動かす。中継はDB・モデル・監視処理を起動しない。本体停止中でも中継は起動してsearch/fetchの一覧を提供する。取得要求時に本体が起動していない、MCPが無効、認証情報を読めない場合は`retrieval_unavailable`を返す。要求ごとに設定を読み直すため、本体起動・再起動・ポート変更後は同じ中継で再試行できる。

開発用には`dotnet`をcommand、ビルドした`LocalRag.Mcp.dll`の絶対パスを先頭のargsに指定できる。現在の配布物は.NETランタイムを同梱するため、別途.NETをインストールする必要はありません。旧rc.3のZIPはフレームワーク依存です。

## ローカルHTTPと保護

### 起動中でも`retrieval_unavailable`になる場合

本体とプラグインの`--data-dir`が同じ保存先を指すか確認する。別の保存先ではMCPポートと認証情報も異なる。本体の起動だけでは、以前の試験用保存先を参照するプラグインの接続は復旧しない。ポートや認証情報を他の保存先へコピーするのではなく、プラグインの保存先指定を本体に揃える。

また、本体のみ更新してプラグイン内の中継が古いままだと、設定形式の変更を読み取れないことがある。2026-11-05の修正で中継はMCP接続設定だけを読み、文書処理設定の版や内容を検証しないようにした。本体は従来どおり設定全体を検証し、検索・全文取得の秘匿検査も本体で実施する。MCP無効設定、接続設定の不正・重複、認証失敗は拒否する。

プラグインは登録元のパッケージを更新して再登録し、キャッシュを直接編集しない。既存の会話が古い中継プロセスを保持している場合は、クライアントの再起動後に新しい会話で確認する。正常な`{"results":[]}`は接続エラーとは異なり、その時点で公開可能な検索結果がなかったことを意味する。取り込み完了・現在の設定による再索引・対象範囲を管理画面で確認する。

中継は既定`http://127.0.0.1:18765/mcp`へ、ユーザー別DPAPIで保存した256bitランダムBearerトークンを付けて接続する。HTTPはStreamable HTTP・ステートレス。SDKはModelContextProtocol.AspNetCore 2.3.0。設定のMCPポート変更は保存時に反映され、古いリスナーを停止する。DBポートと同一の指定は禁止。

HTTPは127.0.0.1のみで待ち受け、Hostの不一致、Origin付きリクエスト、トークンなし・不一致を拒否する。ブラウザから直接の呼び出しやLAN公開は想定しない。トークンをチャット・設定例・ログへ貼り付けない。保存先は`<data-dir>/mcp/server/credentials.dpapi`であり、DBの認証情報とは別である。DPAPIは同じWindowsユーザーで動く悪意あるプログラムからの隔離を提供するものではない。

MCPの処理は同時に最大2件まで受け付け、それ以上は`busy`を返す。AI処理は取り込みと直列化する。待機を含む1呼び出しの上限は100秒。取り込み中・モデル切替中は`cancelled_or_timeout`となる場合があるので、取り込み完了後に再試行する。設定変更・アプリ終了時には進行中のMCP処理をキャンセルして完了を待ち、DBへの参照を解放する。

## 返却と機密検査

searchは単一のMCP text contentにJSONの`{"results":[...]}`を返す。fetchも単一のtext contentにJSONオブジェクトを返す。許可された結果は`id, decision, title, text, url, source`を持ち、チャンクには`start_paragraph, end_paragraph`を付ける。`url`の`localrag://document/<id>`は文書を識別するURIであり、ブラウザで開く公開ページではない。

親子チャンクは既定ON。searchは子のベクトル類似度で検索し、対応する親（Markdownの章、構造のない文書は全文）の原文を`text`へ返す。`parent_chunk_id`は版に結び付いた親の識別子、`section_title`は見出しがある場合の階層名。段落番号は返した親の範囲で、最初に一致した子だけの範囲ではない。同じ親を重複して返さず、一番近い子の順に並べる。内部候補は最大256子のため、指定件数未満になる場合がある。

`id`は引き続き文書UUID。同じ文書から異なる章が返る場合もある。`fetch(id)`にはこの文書UUIDを渡し、親チャンクIDは渡さない。fetchは原文全文を返し、親チャンクID・章名・段落範囲は付けない。searchとfetchのどちらも、原文全体と返却候補・メタデータの秘匿検査、検査後の原文の更新確認を行う。別章の秘匿情報も文書全体を非開示にする。

拒否・判定不能は`id`、`decision`、`source`（原本のフルパス）を返す。本文・要約・コード・章タイトル・段落番号・スコアは返さない。原文と返却候補の両方を、管理画面と同じ機密検査に通す。LLM検査に失敗した場合も本文は返さない。ユーザーが機密検査を無効にした場合だけ`unchecked`として返す。モデルの意味的な誤判定を完全に防ぐものではない。

```json
{"id":"7619c210-8546-4eb5-b598-94834cb6a0d2","decision":"withheld","source":"C:\\Documents\\内部資料.txt"}
```

2026-11-05の仕様変更により、非開示文書でもファイル名・フォルダ名を含む原本パスはMCPクライアントへ提供する。クライアントはこのパスを文字列としてユーザーに提示し、エクスプローラーで原本を開くよう案内する。AIがパスから本文を読み出して機密検査を迂回するための許可ではない。`fetch`への入力は引き続き文書IDのみとする。旧サーバーから`source`が返らない場合はパスを推測しない。

原文が変更・削除された、索引が未完成、現在の設定と異なる場合は取得対象外。fetchは`not_available`を返す。一般的な障害は`retrieval_unavailable`、引数の誤りは`invalid_arguments`とし、例外やモデルの生応答は外部に返さない。MCPの結果は文書データであり、その本文中の指示に従うためのシステムプロンプトとして扱わない。

## ChatGPTから利用する場合

呼び出し側のクエリ作成方針は[Local RAGスキル原本](https://github.com/gafs-ai/Local-RAG/blob/main/plugins/local-rag/skills/search-local-documents/SKILL.md)に定める。対象・処理・条件を含む質問または説明を基本とし、意図を保ったキーワード列も認める。日本語・英語・韓国語・中国語等の優劣は固定せず、利用者の言語から始め、根拠が足りない場合だけ言い換えや別言語を検討する。文書名だけでなく返却箇所の根拠を確認し、必要なら文書IDで全文取得する。

`Package-Plugin.ps1`はこの原本をDesktop／Portable両形式へコピーする。原本の編集はインストール済みプラグインの自動更新ではない。更新を反映する場合はパッケージを再作成し、利用ホストの導入・更新手順で読み直す。キャッシュを直接編集しない。

利用方針は**ChatGPT Business、Windowsデスクトップ優先、ブラウザ版も将来対応**とする。OpenAI API Platform、APIキー、Secure MCP Tunnelを必須条件にしない。ローカルMCPの試験成功、プラグインの登録成功、ChatGPTからの実取得成功は区別する。

### Windowsデスクトップ優先

公式の[デスクトップ用プラグイン](https://developers.openai.com/plugins/deploy/desktop-only)で説明されるローカルstdio方式を使う。Local RAGを常駐させ、同じPC・Windowsユーザーのローカル実行可能な会話からプラグインを選択する。利用可否はBusinessワークスペースのポリシーとデスクトップ環境で確認する。公開ディレクトリへの審査付き提出と、今回の非公開プラグイン登録は別の作業である。

`scripts/Package-Plugin.ps1 -DistributionDirectory <展開済み配布フォルダ>`で、実行ファイル・依存DLL・ライセンスを含む`local-rag.zip`とローカルmarketplaceを生成する。既定のDesktop形式は`.codex-plugin/plugin.json`、`.mcp.json`、検索用スキルを同梱する。互換マニフェストを維持し、現在の配布物は.NET同梱の`./server/LocalRag.Mcp.exe`をプラグイン基準の`cwd: "./"`で実行する。`cwd: "."`は現在のホストで不正として拒否されるため使用しない。以前の検証版は`dotnet ./server/LocalRag.Mcp.dll`を使用していた。`${PLUGIN_ROOT}`が展開されない環境でも固定ユーザーパスを埋め込まずに動作する。

`-Format Portable`はAgent Plugins 1.0の`plugin.json`と`mcp.json`を生成するが、今回のホストではMCPが認識されなかったため、デスクトップの動作確認には用いない。設定・認証情報・文書・DBはどちらにも含めない。既定保存先を変更した場合のみ`-DataDirectory <絶対パス>`を指定し、このPC専用のパッケージとして扱う。

ホストがCodex CLIのローカルmarketplaceを利用する環境では、生成されたmarketplaceのディレクトリを`codex plugin marketplace add <ディレクトリ>`、続いて`codex plugin add local-rag@local-rag-local`で登録できる。これはローカルホストへの登録であり、Businessワークスペースへの登録完了を意味しない。ChatGPTの非公開プラグイン追加、または管理者による[GitHub marketplaceの取り込み](https://learn.chatgpt.com/docs/enterprise/plugin-management)はホストの対応する導入手順で行う。キャッシュを直接編集しない。

2026-11-02時点: MCP宣言の認識・パス展開・本体停止時の中継終了を修正し、ホスト診断でsearch/fetch両方と起動エラーなしを確認した。`scripts/Test-PluginDiscovery.ps1 -MarketplaceFile <marketplace.json>`で再現できる。更新前から続いていた会話にはツールが現れなかったが、**新しい会話でguide.txtの本文・出典・文書IDが返ったことをユーザー提供の結果で確認**した。個々のsearch/fetch呼び出し履歴はこの会話では未確認。ChatGPT上の機密拒否・検査失敗と実文書での実用性評価は残る。

導入・更新後の試験は新しいローカル実行の会話で行い、`Local RAG local packages`版を選択する。検証版は合成文書用保存先に接続する。別途作成したワークスペース側の非公開版は以前の形式のため、今回の成功対象に含めない。この接続試験時点では0.0.0を公開しなかった。現在のリリースは0.26.3。

### ブラウザ版（未実装）

このローカルstdioパッケージはブラウザ上だけでは実行できない。ブラウザ版の将来対応では、API Platformを利用しない認証付きHTTPS MCPの接続経路を別途設計し、BusinessのカスタムMCP接続条件を確認する。現行のループバックHTTPをそのまま外部公開しない。公開先、認証、PCの起動条件、運用費を確定するまでは未対応と表示する。

どちらの方式でも、機密検査を通過してMCPが返した文書内容はChatGPTへ送信される。

## 配布前の確認

- 実MCPクライアントでtools/listにsearchとfetchだけが現れる。
- 合成文書で検索・全文取得、機密文書の存在のみ返却を確認する。
- アプリ終了後は中継から取得できない。再起動後に再接続できる。
- ChatGPTで実際のsearch/fetch呼び出しと回答を確認する。未検証を完了扱いにしない。


### 取り込み中の検索待ち

0.26.3の修正版では、取り込み中のAI呼び出しが完了すると検索・全文取得を優先し、その後に取り込みを再開します。文書全体の完了待ちは不要ですが、未完成文書は返しません。MCPの待機を含む100秒の期限は維持するため、推論1回や検索自体が長い場合は時間切れになることがあります。[処理順と診断ログ](RetrievalPriority-2026-11-10.md)を参照してください。
