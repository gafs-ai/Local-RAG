# Word文書の取り込み（0.26.3）

検索は内容の概要の把握と原本の発見を目的とします。Word・PDFとも、画像や図表が多い文書では情報の完全性が失われる可能性があります。図の意味や配置は再現せず、重要な内容は必ず原本を確認してください。

## 使い方

新規設定には「Word用」（`.docx`・`.docm`・`.doc`）を用意しています。既存設定は上書きしません。更新した場合は「設定」→「テキスト処理」で「追加する処理」から「Word文書：Markdownへ変換」を選び、「設定を追加」→「保存して適用」としてください。監視フォルダ内のWord文書が対象になります。

`.docx`と`.docm`はアプリ内で読み取り専用の変換を行います。Wordの起動やマクロ実行は行いません。旧形式`.doc`だけは、このPCにインストールされたMicrosoft WordとWindows PowerShellを使います。元文書のコピーを専用プロセスで開き、`WordOpenXML`からXMLを読み取って同じ変換処理へ渡します。保存先の原本を変更しません。Wordを導入していない場合は、あらかじめ`.docx`で保存してください。

## 処理の順番

1. WordのXML構造から見出し、本文、箇条書き、表、脚注・後注を取り出してMarkdownにします。見出しスタイルと継承されたアウトラインレベルを使用し、7～9の深いレベルはMarkdownの上限6へ丸めます。
2. ヘッダー・フッターを通常本文から外します。認識できる機密ラベルは冒頭に残します。秘匿検査用には、ラベルとヘッダー・フッターを含む抽出本文も別途保存します。ユーザー独自の機密パターンも、この検査用本文に対して適用されます。
3. 短い太字段落を見出しとして補正し、段落内の手動改行を結合します。どちらもWord用の設定で無効にできます。画面幅による自動折り返しには、そもそも改行を追加しません。
4. 有効ならローカルLLMで見出しレベルと分断された段落を補正します。モデルにはIDと見出しレベル・結合範囲だけを返させ、本文の生成・削除・順序変更を許しません。機密ラベル、表、リスト等は保護します。JSONの不備は1回差し戻し、それでも不正なら変換結果を保持し、履歴に注意を表示します。
5. 分類後は既存のMarkdownと同様に、整形、子チャンク、章単位の親チャンク、親の埋め込み、ベクトル検索へ進みます。新規Word用設定では不要段落のLLM除去を省略し、子・親は機械的な構造処理とします。

LLMの構造補正は小さい入力窓に分けて行います。窓に収まらない段落は切り捨てず、そのまま残します。窓をまたぐ段落結合は行いません。処理済みの窓をDBに保存して中断・再開に対応します。見出し推測や文章のつながりは誤ることがあるため、結果を確認し、必要なら補正を無効にしてください。

## 設定

| 項目 | 初期値・用途 |
| --- | --- |
| 入力の扱い | Word文書：Markdownへ変換 |
| 短い太字段落を見出しとして補正 | ON。100文字以内で文末の句点等がない太字段落をレベル2と推定 |
| 段落内の手動改行を結合 | ON。日本語・中国語は通常空白を挟まず、欧文・韓国語は空白で接続 |
| LLMで見出し・分断された段落を補正 | ON。単独でOFFにできる |
| Word構造補正プロンプト | プロンプト管理でコピー・新規作成し、選択できる |
| 親チャンク | 章立てで構成。最小500文字、最大4000文字。既存のMarkdownと同じ境界調整 |

詩、住所、歌詞など改行自体に意味がある文書は、改行結合とLLM補正をOFFにしてください。Word用では文字コードを手動指定する必要がないため、その欄は表示しません。

## 検索・再処理

MCPの`search`は既存の構造検索を使い、`fetch`は補正後のMarkdown全文を返します。元のWordファイルのパスも返します。検索と全文取得の両方で共通の秘匿検査を行います。機密検査は、補正によって失われてはならない抽出時の本文とヘッダー・フッターを使用します。先頭・末尾の行数は、この検査用テキストの行数です。Wordの印刷ページ上の行数ではありません。

元ファイルのバイト列をSHA-256で確認し、処理途中の更新・検索時点の更新があれば古い結果を返しません。変換方法・構造補正プロンプト等の処理情報を保存します。Embeddingモデルだけの変更では完了した構造補正を再利用し、同じ入力のベクトルも従来どおり再利用します。変更のない`.doc`を毎回Wordで開き直すことも避けます。

## 対応範囲と制約

- 本文の文字列を扱うRAG向け変換です。ページの見た目を再現するものではありません。画像は存在と代替テキストを表し、OCR・画像検索・画像そのものの返却は未対応です。
- 表はMarkdownへ変換します。結合セルは文字列を保持しますが、元のセル配置は完全には再現しません。変更履歴は変更後の本文を使用し、削除された文言・コメントは取り込みません。該当する文書には注意を表示します。
- 数式、埋め込み文書、外部HTMLの取り込み等、本文の欠落が懸念される未対応要素は保留します。暗号化・パスワード保護・破損した文書も保留します。
- Wordパッケージは64MiB以内、展開後128MiB以内、XML部分ごとに16MiB以内。変換後本文と秘匿検査用本文には設定の文書文字数上限も適用します。
- `.doc`変換は2分で打ち切ります。マクロ・リンクの自動更新を無効にし、専用WordのPIDと開始時刻が一致する場合だけ後片付けします。利用者が開いたWordをプロセス名だけで終了しません。Officeの導入状態や組織の実行ポリシーによって変換できない場合は`.docx`で保存してください。

構造仕様はMicrosoftの[WordprocessingMLの構造](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)、[アウトラインレベル](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.outlinelevel)、[Wordのマクロ制御](https://learn.microsoft.com/en-us/office/vba/api/word.application.automationsecurity)を参照しています。
