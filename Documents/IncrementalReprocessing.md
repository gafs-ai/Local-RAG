# 設定変更と工程単位の再処理

## 方針

文書データに処理方法・適用設定・入力ハッシュ・出力ハッシュを工程別に保存する。全体設定が変わったという理由だけで、全ファイルの分類や説明を作り直さない。同じ入力と同じ工程設定なら結果を再利用し、やり直した工程の出力が変わらなければ後続工程も再利用する。

| 変更 | 再処理する範囲 |
|---|---|
| 別拡張子の設定、ルート名・プロンプト名、未使用プロンプト | 対象文書の実効処理が同じなら不要。分類入力に使うカテゴリ名・説明文は分類の依存情報に含む |
| 分類プロンプト・分類候補・言語モデル | 有効な分類を再実行。分類結果が同じなら、独立した後続結果を再利用 |
| 選択カテゴリの整形 | 整形を再実行。出力が同じなら結合結果を再利用 |
| 子の結合設定 | 子の作成以降。親の入力が同じなら親を再利用 |
| 親のまとめ設定 | 親の作成以降。子の結合結果を再利用。ただしMarkdownの境界・長さが変わる場合は段落構造への影響を確認 |
| 親説明プロンプト・言語モデル | 対象の親説明。原文や子の結合を再利用 |
| コード説明プロンプト・言語モデル | コード説明。構文解析結果を再利用 |
| Embeddingモデル・Embedding版 | 既存の分類・整形・説明を再利用し、入力上限に合わせて再分割・埋め込み。モデル間のベクトル流用はしない |
| 検索の重み、秘匿判定、MCP、監視間隔・優先度 | 取り込みの再処理は不要。取得設定は次の取得から適用 |
| 除外・監視対象解除 | 索引を非公開化。再追加時は原本と工程の一致を確認して再利用 |

## 保存する情報

`TextDocumentState.Processing`に実効プロファイルの識別子と工程別の`ProcessingReceipt`を保存する。各工程は、処理方式の版、実効パラメータ、モデル識別子、入力・出力のハッシュを持つ。プロンプトはIDの名称ではなく内容で比較する。実効設定には、選択された拡張子・カテゴリで使用するものだけを含める。

子の結合結果（`PreparedChildren`）と親への所属確定後の結果（`HierarchyChildren`）を、最終的な埋め込み用チャンクと分離する。モデルの入力上限が小さくなった場合は元の子を損失なく小分けにし、上限が大きくなっても既存の子を無理に結合し直さない。結合方針を変えたい場合は結合設定を変更する。

親説明には親原文のハッシュと説明生成方法を記録し、同じ親原文の完成済み説明を再利用する。未完了の説明は入力の分割と進捗位置が一致する場合だけ再開する。

Embeddingモデル変更により、以前は収まっていた親全文が新しい入力上限を超えた場合は、選択された方針に従う。「長い場合は説明を生成」なら未作成の親説明だけを生成し、「収まる親全文だけ」ならその親の埋め込みを省略する。すでに生成済みの説明があれば作り直さない。子の索引は維持する。

同一文書・同一Embedding空間・同一入力の既存ベクトルは、新しい文書版へコピーできる。返却範囲・親IDが変わっても本文入力が同じならAPIで埋め込みを作り直す必要はない。モデル、接続先、Embedding版、次元が異なる空間からはコピーしない。

## 公開・再開と互換性

再処理対象の文書は作業開始時に非公開化し、全工程の完了・原本の再確認後にまとめて公開する。途中停止時は保存済み工程・埋め込み件数から再開する。旧版の断片を新版へ混ぜて返さない。

検索は各文書の実効プロファイルが現在設定に適合する版だけを候補にする。無関係な拡張子の変更で有効な文書まで検索不能にしない。設定変更で不適合となった版は、まだ再処理の順番が来ていなくても返さない。

ANN候補の件数を制限する前に、適合した文書版IDでフィルタする。これにより不適合な旧版が上位候補を占有するのを防ぐ。判定用一覧は文書本文・工程別プロンプトを取得しない。取得直前の原本ハッシュ・監視範囲・除外・秘匿検査は引き続き実行する。

工程情報のない旧データは、旧全体設定IDが一致する場合のみ既存結果へ工程情報を付与する。不一致の場合、過去の実効設定を推測して流用せず、初回だけ安全側に再構築する。元ファイルが変わった場合も工程を再計画する。

モデル名が同じまま内部の重みやサーバーの実装が置換されたことまでは検出できない。Embeddingモデルを同名で更新した場合はEmbedding版を変更する。今後はサーバーから安定したモデル版情報を取得できる場合に照合へ追加する。

## 運用

設定保存後、監視中なら新設定で直ちに探索を開始する。停止中なら停止を維持し、次の「今すぐ実行」または監視再開で再処理する。処理方法が適合しない文書は「旧設定の記録・再処理待ち」と表示する。対象外の拡張子の変更や検索・秘匿設定の変更だけでは、この待ち表示にしない。

工程情報と再利用対象はアプリのDB内に保存する。「データを初期化する」で文書・文書版・ベクトルを削除すると、これらの情報も削除される。元ファイルや設定は保持する。完了済みの旧版・ベクトルは従来どおり残るため、長期運用での履歴の保存期間・自動整理は別途検討する。
