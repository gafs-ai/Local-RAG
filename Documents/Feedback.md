# フィードバック

画面下部の「フィードバック」から、開発者へメッセージを送信できます。

1. 「改善要望」「バグまたはバグの疑いの報告」「その他」から種類を選びます。
2. 内容を8,000文字以内で入力します。不具合の場合は、操作手順・期待した動作・実際の動作を記載してください。
3. 「利用統計を送信する（バグ報告時には送信をお願いします）」を確認します。初期状態はONです。添付したくない場合は外してください。
4. 「送信する」を押します。送信完了が表示されたら閉じます。

入力したメッセージは、そのまま開発者へ送られます。個人情報・機密情報を記入しないでください。ファイル・ログ・スクリーンショットを自動添付することはありません。下書きはこの画面を開いている間だけ保持し、閉じると失われます。

## 利用統計の添付

チェックがONの場合、この報告に機材の種類・メモリ容量区分・使用モデル・Local RAGの版・設定の変更有無と、収集済みの拡張子別処理件数・時間を添付します。「添付する利用統計を確認」で確認できます。通常は送信時点の情報を添付し、同じ報告を再送するときは最初の送信時と同じ情報を使用します。

自動送信の設定とは独立しています。自動の利用統計をOFFにしていても、この報告への添付を選べます。その場合は環境・設定の情報だけを添付し、過去の処理履歴を読み直して送ることはありません。自動送信のON/OFF・未送信の集計・24時間の送信間隔は変更しません。

利用統計のために文書本文・ファイル名・パス・フォルダ設定・プロンプト本文・ユーザー名・端末IDを取得することはありません。CPU・GPU・AIモデルは既知の名称またはunknown／otherにまとめます。NPUだけはWindowsから取得した名称をそのまま添付し、正常な列挙で見つからなければ「なし」、取得失敗は「不明」と表示します。詳細は[利用統計](UsageStatistics.md)を参照してください。自分でメッセージ欄へ書いた内容は、この自動的な除外の対象ではありません。

## 送信失敗・中止

通信に失敗しても、自動で再送しません。同じ画面で内容を変えずに「送信する」を押すと、同じ送信番号を使って再送し、既に受信されていても重複登録を防ぎます。内容・種類・利用統計のチェックを変更した場合や画面を閉じて開き直した場合は、新しい報告になります。

「中止して閉じる」またはアプリの完全終了で処理を中止します。通信のタイミングによっては既に受信されている場合があります。送信先が組み込まれていない開発ビルドでは送信できません。

受信側では、報告本文と添付された利用統計を対応付け、許可された開発者だけが一覧・詳細を確認します。ユーザーや端末を識別するための固定IDは付けません。添付した処理件数を定期送信の統計へ加算することもありません。

報告と添付統計の表示・保存期間は90日です。期限を過ぎたデータは受信に伴って順次削除するため、受信が停止している期間は物理削除が遅れることがあります。重複登録を防ぐ送信番号は30日を上限の目安として保持します。
